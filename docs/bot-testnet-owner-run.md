# Owner-led BOT testnet wallet checkpoint

Open https://settleref.pages.dev/bot-testnet/ in a browser with a wallet extension that you control. Use only a disposable BOT **testnet** account funded with valueless test BOT. The page does not import keys, connect a faucet, switch networks for you or support BOT mainnet. Never enter a seed or private key into SettleRef. This hosted wallet integration has passed local fake-provider checks, but it has not yet passed a real-wallet run.

1. Check that the wallet itself shows BOT testnet chain **968**, the account you control, and a sufficient test-token balance. Connect Wallet, then review the displayed account, fresh receiver, settlement contract, 0.01 tBOT temporary principal and provisional gas limits. Do not approve a wallet prompt whose network, recipient, value or fee differs from the reviewed plan. Wallet fee editing can exceed the app's estimates.
2. Select the explicit plan confirmation and start. Approve each distinct wallet request separately: deploy your owned receiver; pay 0.01 tBOT through the pinned settlement contract to that receiver; withdraw the receiver balance to the same owner account. Wait for the app's receipt and canonical-block checks between steps. The principal return requires the **same owner account**; a different account cannot withdraw it. Gas is spent even if a transaction later fails.
3. After the app reports verified completion, download the evidence JSON. Keep a copy of the original transaction hashes and the report before starting another run. The report is RPC-backed evidence from the connected provider, not independent consensus or proof of invoice authenticity.

For a **wrong network or account**, stop before approving any request. The runner should block and keep existing evidence. Return to chain 968 and the original account only after reviewing the state again. A chain or account change during a run revokes the current session's verification.

If you **cancel a wallet prompt**, read the app state before doing anything else. A returned rejection remains stopped with no automatic retry; a missing response or missing hash is an **unknown outcome** and must not be re-sent. Check wallet activity and the original hash if one later appears. Resume performs read-only reconciliation of a known original hash, then may ask for the *next distinct* transaction; it never automatically repeats the earlier one.

If **payment succeeds but owner return fails**, the principal can remain in the owner-controlled receiver. Preserve the receiver address and original hashes, export evidence when available, and use only the owner account to investigate or recover; do not create a new payment ID or deploy a second receiver to hide an uncertain result. If receipt, event, bytecode, account, fee or canonical-block checks disagree, stop and retain the original evidence for review.

No owner wallet request was sent as part of source sync or this checklist. Local fake-provider tests cover wrong chain/account, lost responses, known-hash recovery, mismatching receipts, rejected return and interrupted prompts. They do not execute a real wallet or substitute for this owner-led testnet checkpoint.
