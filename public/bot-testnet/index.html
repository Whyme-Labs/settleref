No run started.

    If a wallet response has no hash, the outcome is unknown. The runner stops; it never automatically re-sends. A delayed wallet response may supply the original hash later. The held-hash verification button checks the original hash only and never opens a wallet prompt. Resume checks a pending original hash, then may request the next distinct transaction for its own wallet approval. A wallet or chain change stops the run. The prior browser journal is never cleared for an unresolved run.

    Trust boundary

    The app uses your injected wallet provider for chain data and wallet prompts. It checks a pinned testnet genesis, reviewed settlement runtime, an owner-controlled receiver, exact intent, receipt/event and provider-reported finality. A single provider is not independent consensus. The newer wallet integration has local fake-provider tests; those fixtures do not execute Solidity. This revision's type-2 recovery path has not been qualified with a live owner wallet.

    No mainnet code path, account funding, faucet request, private key import or automatic signing is included. The app requests a legacy gas price and verifies a wallet-converted type-2 transaction only when both signed fee maxima remain within that reviewed price cap. App fee caps are engineering defaults, not a hard wallet spending limit. Inspect every wallet prompt.
